# 成品化收尾清单：Experiment Report Skill

这个项目的核心功能已经成型，后续不按“重做”处理。成品化目标是让它可以稳定演示、交付和复查。

## 一句话定位

面向中文大学实验报告和课程设计报告的本地生成流水线：把题目、教程链接、正文、学校模板、截图证据和版式检查收成一条可复查的 `docx` 交付链路。

## 标准演示流程

1. 打开项目管家，搜索 `实验报告`。
2. 启动 `Experiment Report Skill` 网页界面。
3. 选择报告类型：实验报告或课程设计报告。
4. 使用内置示例或上传学校模板。
5. 填入课程名、实验名、姓名、学号、班级。
6. 上传 2 到 4 张截图，或填写本地截图路径。
7. 选择生成模式，点击生成报告。
8. 打开生成的 `docx`，检查标题、正文、图片、图注和页眉页脚。
9. 如开启 PDF，确认 PDF 和预览图生成成功。

## 交付验收

- 网页入口能从项目管家启动。
- 空模板、示例模板、课程设计模板至少各跑通一次。
- 生成目录里包含最终 `docx`、中间正文、元数据和日志。
- 截图插入位置可解释，图注编号连续。
- 学生姓名、学号、班级、课程名、实验名能进入模板对应位置。
- 失败时给出中文错误，不只显示脚本堆栈。
- README 或演示文档能让别人按步骤复现一次。

## 下一次迭代只做这些

- 固定一个“最稳演示样例”，用于录屏和截图。
- 给网页界面补一个“示例数据一键填入”按钮。
- 给输出目录加一个 `交付清单.md`，列出本次生成了哪些文件。
- 增加一个轻量检查：生成后自动提示缺图、缺姓名、缺课程名。

## 不做的事

- 不把它扩成万能文档生成器。
- 不同时支持太多学校模板规则。
- 不为了视觉效果牺牲 Word 模板稳定性。
- 不在成品化阶段大改现有流水线结构。
