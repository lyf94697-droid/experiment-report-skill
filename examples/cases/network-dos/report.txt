实验目的

本次计算机网络课程实验围绕“局域网搭建与常用 DOS 命令使用”展开，要求在 VMware Workstation 中建立一个由两台 Windows Server 2019 虚拟机组成的仅主机局域网，并完成静态 IPv4 地址规划、网络参数核验、双向连通性测试和 ARP 邻居缓存分析。通过完整配置和验证过程，掌握 IPv4 地址、子网掩码、网络号与主机号之间的关系，理解同一网段主机无需经过默认网关即可直接通信的条件。

实验同时要求熟练使用 ipconfig、ping、arp、netsh 等 DOS 命令。ipconfig 用于核对网卡地址、子网掩码和 DHCP 状态；ping 用于通过 ICMP Echo 报文验证协议栈与端到端连通性；arp -a 用于查看 IP 地址到 MAC 地址的动态映射；netsh 用于从命令行复核接口配置。最终应形成“配置—验证—分析—排错”的闭环，而不是仅以能否收到 ping 回复作为唯一结论。

实验完成标准如下：两台主机分别使用 192.168.10.11/24 与 192.168.10.12/24；双方执行 ping 均收到 4 次回复且丢包率为 0%；通信后 ARP 缓存中出现对端主机的动态条目；能够复现一次错误配置并按照分层思路定位原因。

实验环境

宿主机操作系统为 Windows 11，虚拟化软件为 VMware Workstation 17。实验创建两台 Windows Server 2019 虚拟机，主机名分别设置为 LAB-A 和 LAB-B，虚拟网卡均连接到 VMnet2 仅主机网络。为避免 DHCP 自动分配地址干扰实验，两台虚拟机均关闭 DHCP，使用静态 IPv4 地址。

地址规划如下：

1. LAB-A：IPv4 地址 192.168.10.11，子网掩码 255.255.255.0，MAC 地址 00-0C-29-11-0A-01。
2. LAB-B：IPv4 地址 192.168.10.12，子网掩码 255.255.255.0，MAC 地址 00-0C-29-12-0B-02。
3. 网络地址：192.168.10.0/24；广播地址：192.168.10.255；可用主机范围为 192.168.10.1～192.168.10.254。
4. 本实验不访问外部网络，因此默认网关和 DNS 服务器保持为空。

实验前确认两台虚拟机处于启动状态，网卡未被禁用，VMnet2 在两台虚拟机中的连接方式一致。Windows 防火墙保留开启状态，但允许“文件和打印机共享（回显请求 - ICMPv4-In）”规则，以便接收 ping 请求。

实验原理或任务要求

IPv4 地址由网络号和主机号组成。地址 192.168.10.11 与 255.255.255.0 按位与运算后得到网络地址 192.168.10.0；192.168.10.12 进行同样运算也得到 192.168.10.0，因此两台主机判断彼此位于同一直接连接网段。发送端在发出 IP 数据包前，需要通过 ARP 广播询问目标 IP 对应的 MAC 地址，收到应答后将映射写入邻居缓存，再以以太网帧形式发送数据。

ping 命令首先构造 ICMP Echo Request 报文。目标主机协议栈正常、地址配置正确且安全策略允许时，会返回 ICMP Echo Reply。回复中的 time 字段反映往返时延，TTL 字段反映报文剩余生存时间。本实验位于同一宿主机内部的虚拟交换网络，正常往返时延应小于 1 ms。连续发送 4 个报文并获得 0% 丢包，能够说明当前测试时段的三层连通性稳定，但还需要结合 ARP 缓存判断二层地址解析是否完成。

ARP 缓存条目分为动态和静态两类。执行 arp -a 后，如果能够在接口 192.168.10.11 下看到 192.168.10.12 与 00-0C-29-12-0B-02 的动态映射，说明主机 A 已通过广播解析出主机 B 的物理地址。清理缓存后首次 ping 可能包含 ARP 解析过程，因此首次响应耗时可能略高；后续报文可直接使用缓存条目。

实验任务还要求建立规范的故障定位顺序：先测试本地协议栈，再检查本机地址与掩码，然后判断双方是否处于同一网段，接着检查 ARP 解析，最后检查防火墙或接口状态。该顺序能够缩小问题范围，避免无依据地反复重启系统。

实验步骤

1. 创建并连接仅主机网络。打开 VMware Workstation 的虚拟网络编辑器，确认 VMnet2 类型为 Host-only，网段设置为 192.168.10.0，子网掩码为 255.255.255.0，并关闭该网段的 DHCP 服务。分别进入 LAB-A 和 LAB-B 的虚拟机设置，将网络适配器连接到 VMnet2，勾选“已连接”和“启动时连接”。

2. 配置 LAB-A 静态地址。进入“网络和 Internet 设置—更改适配器选项”，打开 Ethernet0 的 IPv4 属性，将地址设置为 192.168.10.11，子网掩码设置为 255.255.255.0，默认网关和 DNS 保持空白。保存后使用 ipconfig /all 核对 DHCP Enabled 为 No、IPv4 Address 为 192.168.10.11、Subnet Mask 为 255.255.255.0。

3. 配置 LAB-B 静态地址。使用相同方法将 IPv4 地址设置为 192.168.10.12/24。随后执行 netsh interface ipv4 show config name="Ethernet0"，确认接口地址、前缀长度和 DHCP 状态与地址规划一致。再从 LAB-B 执行 ping 192.168.10.11 -n 1，初步验证反向通信。

4. 检查本地协议栈。在两台主机中依次执行 ping 127.0.0.1 和 ping 本机 IPv4 地址。127.0.0.1 测试通过表示 TCP/IP 协议栈工作正常；本机地址测试通过表示网卡接口已正确绑定 IPv4。若本机地址无法响应，应先检查网卡状态与地址冲突，而不是立即排查虚拟交换机。

5. 执行双向连通性测试。在 LAB-A 中运行 ping 192.168.10.12 -n 4，记录每次响应的字节数、往返时间、TTL 和丢包率；在 LAB-B 中运行 ping 192.168.10.11 -n 4，确认结果一致。测试期间不进行其他网络操作，以减少干扰。

6. 观察 ARP 地址解析。先在 LAB-A 中执行 arp -d * 清理动态缓存，再执行 arp -a，确认没有对端条目。随后重新 ping 192.168.10.12，再次运行 arp -a，记录新增的 192.168.10.12 动态映射。该过程验证了“先 ARP 解析、后发送 ICMP 报文”的实际行为。

7. 复现并排查错误。将 LAB-B 的子网掩码临时改为 255.255.0.0，并记录双方对网络范围判断不一致带来的风险；随后恢复为 255.255.255.0。再禁用 LAB-B 的 ICMPv4 回显规则，观察 LAB-A 出现请求超时；恢复规则后重测，确认通信恢复。每次修改只改变一个变量，以便确定故障原因。

实验结果

LAB-A 执行 ipconfig /all 后显示 IPv4 Address 为 192.168.10.11、Subnet Mask 为 255.255.255.0、DHCP Enabled 为 No；LAB-B 使用 netsh 检查得到 IP Address 192.168.10.12、Subnet Prefix 192.168.10.0/24。两台主机的网络号均为 192.168.10.0，地址未重复，配置与规划一致。

从 LAB-A 向 192.168.10.12 连续发送 4 个 ICMP Echo Request，收到 4 个 Reply，单次往返时间均小于 1 ms，TTL 为 128。统计结果为 Sent = 4、Received = 4、Lost = 0，丢包率 0%。LAB-B 反向测试同样为 4 发 4 收。该结果说明虚拟交换链路、双方 IPv4 协议栈与 ICMP 入站规则均工作正常。

清理 LAB-A 的 ARP 缓存后，首次 ping 触发地址解析。通信完成后执行 arp -a，在接口 192.168.10.11 下出现“192.168.10.12  00-0c-29-12-0b-02  dynamic”条目，与 LAB-B 的网卡 MAC 地址一致。由此可确认端到端通信不是由错误的缓存或其他主机代答，而是建立在正确的二层映射上。

结果汇总如下：

1. 地址与掩码核验：2/2 台主机通过。
2. 本地协议栈测试：4/4 项通过，包括两台主机的回环与本机地址测试。
3. 双向 ping：共发送 8 个报文，接收 8 个，丢包 0 个。
4. ARP 映射：双方均出现对端动态条目，IP 与 MAC 对应正确。
5. 故障恢复：恢复 /24 掩码和 ICMPv4 规则后，通信重新达到 0% 丢包。

问题分析

故障复现表明，仅看到“请求超时”无法直接判断故障位于哪一层。当 ping 127.0.0.1 成功但 ping 本机地址失败时，应检查接口是否启用、IPv4 是否绑定或地址是否冲突；当本机测试成功但对端失败时，应比较双方 IP 与子网掩码，确认是否具有一致的网络边界；当地址规划正确但 arp -a 中没有对端条目时，应检查虚拟网卡是否连接到同一 VMnet、链路是否中断；当 ARP 条目存在而 ICMP 仍超时时，应重点检查防火墙规则。

本次将 LAB-B 掩码临时改为 255.255.0.0 后，LAB-B 会把 192.168.0.0/16 视为本地网络，而 LAB-A 仍把 192.168.10.0/24 视为本地网络。虽然 192.168.10.11 与 192.168.10.12 在这一特定组合下仍可能直接解析，但双方对网络边界的理解已不一致，后续扩展地址或接入路由器时会导致不对称转发，因此必须按照统一规划恢复 /24。这个现象说明“当前能 ping 通”不等于地址设计正确。

禁用 ICMPv4 回显规则后，ARP 仍能解析到对端 MAC，但 ping 显示请求超时。该现象能够区分二层链路与安全策略问题：ARP 成功说明广播和二层通信正常，ICMP 无回复则应检查目标协议栈或防火墙。恢复规则后无需修改地址即可恢复通信，进一步验证了故障原因。

实验中还应注意 ARP 缓存可能掩盖地址变化。如果更换主机地址或复制虚拟机后 MAC 地址发生变化，应执行 arp -d * 清理旧条目再测试。否则短时间内可能继续使用失效映射，造成间歇性故障。

实验总结

本次实验完成了从网络规划、主机配置到连通性验证和故障定位的全过程。通过对 192.168.10.11/24 与 192.168.10.12/24 的配置，明确了同一局域网中网络号一致、地址唯一、链路处于连接状态以及安全策略允许通信的重要性。ipconfig 与 netsh 提供了配置证据，ping 提供了端到端测试数据，arp -a 则补充了二层地址解析证据。

实验最大的收获是建立了可复用的排错方法：先确认本机协议栈，再核对地址与掩码，然后观察 ARP，最后检查防火墙。相比只记录“能通”或“不能通”，这种方法能够给出故障发生位置和恢复依据。后续进行跨网段通信实验时，还需要在本实验基础上加入默认网关、路由表和 tracert 分析，进一步理解主机如何选择直连转发或经路由器转发。
