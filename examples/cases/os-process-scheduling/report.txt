实验目的

本次“进程调度算法模拟”实验通过编程实现先来先服务 FCFS、非抢占式短作业优先 SJF 和时间片轮转 RR 三种调度算法，在相同进程集合上记录执行序列、完成时间、等待时间、周转时间、带权周转时间、首次响应时间和上下文切换次数。实验目标不是只输出一个调度顺序，而是建立统一、可复现的模拟框架，解释不同调度策略在平均性能、公平性和响应速度之间的取舍。

通过实验应掌握以下内容：理解进程控制块中到达时间、服务时间、剩余时间和状态字段的作用；正确维护就绪队列与系统时钟；能够处理就绪队列暂时为空、多个进程同时到达和时间片耗尽等边界情况；能够根据原始调度记录计算评价指标，并通过断言和边界用例验证结果。

验收标准为：三种算法均能在固定测试集上生成完整甘特图；每个进程只完成一次且累计执行时间等于服务时间；完成时间不早于到达时间；6 组边界测试全部通过；SJF 的平均等待时间低于 FCFS，RR 在 q=2 时的平均首次响应时间低于另外两种算法。

实验环境

实验主机使用 Windows 11 64 位操作系统，处理器为 8 核 x64，内存 16 GB。开发工具为 Visual Studio Code 1.92，Python 版本为 3.11.9。程序由 scheduler.py、models.py、metrics.py 和 test_scheduler.py 组成，输入数据保存在 processes.csv 中，运行结果输出到 results/scheduling-summary.json。

进程测试集固定为：

P1：到达时间 0，服务时间 8。
P2：到达时间 1，服务时间 4。
P3：到达时间 2，服务时间 9。
P4：到达时间 3，服务时间 5。
P5：到达时间 4，服务时间 2。

时间片轮转算法的时间片 q 设置为 2。所有算法均忽略真实操作系统中的进程切换耗时，用离散整数时间片推进模拟时钟，因此结果只反映调度策略本身，不代表具体硬件上的实际毫秒数。

实验原理或任务要求

FCFS 按进程到达就绪队列的先后顺序运行，属于非抢占式算法。当前进程一旦获得 CPU，就持续执行到完成。算法结构简单、切换次数少，但如果长进程先到达，后续短进程会产生较长等待，即“护航效应”。在本测试集中，P1 首先到达并连续运行 8 个时间片，P2～P5 必须等待 P1 完成。

非抢占式 SJF 每次从已经到达且尚未完成的进程中选择服务时间最短者运行。该策略在已知服务时间的条件下有利于降低平均等待时间，但长进程可能长期等待。由于时间 0 时只有 P1 到达，SJF 仍先执行 P1；P1 完成后，按照 P5、P2、P4、P3 的服务时间顺序调度。

RR 使用先进先出的循环队列。队首进程最多运行 q 个时间片；如果未完成，则更新剩余时间并加入队尾；如果完成，则记录完成时间并移出系统。每次时间片结束时，需要先把运行期间新到达的进程加入队列，再决定当前进程是否重新入队，否则会改变公平性。q 过大时 RR 接近 FCFS，q 过小时首次响应变快，但上下文切换次数增加。

评价指标定义如下：

1. 周转时间 = 完成时间 - 到达时间。
2. 等待时间 = 周转时间 - 服务时间。
3. 带权周转时间 = 周转时间 / 服务时间。
4. 首次响应时间 = 第一次获得 CPU 的时刻 - 到达时间。
5. 平均指标为所有进程对应指标的算术平均值。

程序必须保持以下不变量：任一进程的剩余时间不能小于 0；每个进程累计运行时间必须等于其服务时间；完成进程不能再次进入就绪队列；系统时钟只能单调递增；就绪队列为空但仍有未到达进程时，时钟应直接推进到最近到达时刻。

实验步骤

1. 建立进程数据模型。使用 dataclass 定义 Process，字段包括 pid、arrival、burst、remaining、first_start、completion 和 slices。remaining 初始化为 burst，first_start 初始为空，slices 保存每次占用 CPU 的起止时刻，用于绘制甘特图和复核累计执行时间。

2. 实现统一输入校验。读取 processes.csv 后，检查 PID 是否唯一、到达时间是否为非负整数、服务时间是否大于 0。对于空集合，程序输出“无可调度进程”并返回空统计；对于非法数据，抛出 ValueError，避免算法内部出现无限循环。

3. 实现 FCFS。先按 arrival 和输入序号稳定排序。若当前时钟小于进程到达时间，将时钟推进到 arrival；记录首次开始时间，连续运行 burst 个时间片，更新完成时间和执行片段。算法结束后调用统一 metrics 函数计算各项指标。

4. 实现非抢占式 SJF。维护未完成进程列表，每轮筛选 arrival <= current_time 的候选集合；若候选为空，将时钟推进到下一到达时刻；否则按照 burst、arrival、输入序号排序并选取首项。进程运行到完成后再进入下一轮选择。

5. 实现 RR。用 deque 保存就绪队列，并使用 next_index 指向尚未入队的进程。每次循环先加入到达时间不大于当前时钟的进程；队列为空时推进时钟并重新入队；队列非空时取出队首，运行 min(q, remaining) 个时间片。运行结束后先加入这段时间内新到达的进程，再将未完成的当前进程放入队尾。

6. 生成调度记录。每次 CPU 分配都记录 start、end 和 pid。FCFS、SJF 形成较长连续区间；RR 会形成多个短区间。根据记录绘制三行甘特图，并核对每个进程各区间长度之和等于 burst。

7. 计算并导出统计。metrics.py 根据 completion、arrival、burst 和 first_start 计算等待时间、周转时间、带权周转时间和首次响应时间，输出进程明细与算法平均值。结果保存为 JSON，便于后续生成图表。

8. 执行单元与边界测试。测试内容包括首进程晚于时间 0、多个进程同时到达、所有服务时间为 1、RR 的 q=1、空进程集合以及服务时间为 0 的非法输入。运行 python -m unittest 后共执行 31 个断言，全部通过。

实验结果

FCFS 调度序列为 P1(0～8)、P2(8～12)、P3(12～21)、P4(21～26)、P5(26～28)。对应等待时间分别为 0、7、10、18、22，平均等待时间 11.40；周转时间分别为 8、11、19、23、24，平均周转时间 17.00。P5 虽然服务时间只有 2，但由于最后到达并排在长进程之后，等待 22 个时间片，护航效应明显。

SJF 调度序列为 P1(0～8)、P5(8～10)、P2(10～14)、P4(14～19)、P3(19～28)。等待时间分别为 P1=0、P2=9、P3=17、P4=11、P5=4，平均等待时间 8.20；平均周转时间为 13.80。与 FCFS 相比，平均等待时间降低 3.20，降幅约 28.1%；平均周转时间同样降低 3.20。P3 作为最长进程被推迟到最后，说明 SJF 的整体平均性能改善可能以长进程等待增加为代价。

RR(q=2) 的主要执行片段为 P1、P2、P3、P1、P4、P5、P2、P3、P1、P4、P3、P1、P4、P3、P3。P5 在时间 10 首次获得 CPU，并于时间 12 完成；P2 于 14 完成；P1、P4、P3 分别于 24、25、28 完成。平均等待时间 13.00，平均周转时间 18.60，均高于 FCFS 和 SJF；但平均首次响应时间仅 2.80，显著低于 FCFS 的 11.40 和 SJF 的 8.20。

三种算法都在时间 28 完成全部 5 个进程，因此忽略切换开销时吞吐率相同，均为 5/28。FCFS 与 SJF 的进程间切换各为 4 次；RR 的调度片段多，切换次数为 14 次。实际系统中每次切换需要保存和恢复上下文，因此 RR 的有效吞吐率还会受到切换开销影响。

带权周转时间能够反映不同长度进程的相对等待程度。FCFS 中 P5 的带权周转时间为 24/2=12.00，远高于 P1 的 8/8=1.00；SJF 将 P5 提前后，该值下降到 6/2=3.00；RR 中 P5 的带权周转时间为 8/2=4.00。该结果进一步说明，单看平均周转时间无法完全评价短进程体验。

边界测试共 6 组，执行结果全部通过。首进程到达时间为 3 时，时钟正确推进到 3，没有产生负等待时间；多个进程同时到达时，FCFS 保持稳定输入顺序，SJF 按服务时间排序；q=1 时 RR 正确递减剩余时间；空集合返回空结果；服务时间为 0 的输入被校验层拒绝。程序总计 31 个断言通过，未发现进程重复完成或剩余时间为负的情况。

问题分析

第一次实现 RR 时，当前进程在时间片结束后立即重新入队，而运行期间到达的新进程随后才加入队列。这会使当前进程比新到达进程多获得一次优先机会，破坏轮转公平性。修正方法是先将 arrival <= current_time 的新进程全部入队，再把未完成的当前进程放到队尾。加入针对到达边界的测试后，调度序列与手工推演一致。

第二个问题是就绪队列为空时使用 current_time += 1 逐步推进。虽然结果正确，但当下一进程很晚到达时会产生大量无意义循环。程序改为直接设置 current_time = min(next_arrival)，既提高效率，也明确表示 CPU 空闲区间。甘特图生成时可选择显示 Idle 区间，以区分算法等待和系统无任务。

统计阶段曾出现“等待时间 = 开始时间 - 到达时间”的错误定义。该式只适用于非抢占式算法，RR 进程可能多次等待，必须使用周转时间减服务时间。修正后 RR 的平均等待时间由错误值 2.80 调整为 13.00，而 2.80 实际是平均首次响应时间。该问题说明评价指标必须与调度模型一致。

时间片 q 对 RR 结果影响明显。q=1 时首次响应更快，但片段与切换次数增加；q=8 时多数进程一次即可完成，算法逐渐接近 FCFS。本实验选择 q=2，是为了让轮转过程清晰可见。真实系统应结合时钟中断频率、交互负载和上下文切换成本选择时间片。

实验结果还表明不存在对所有场景都最优的单一算法。SJF 在已知服务时间的离线任务中具有较低平均等待时间，但服务时间通常只能估计，并可能造成长作业饥饿；RR 更适合强调响应和公平性的交互系统；FCFS 则适合实现成本低、到达顺序具有业务意义的队列。

实验总结

本次实验完成了 FCFS、SJF 和时间片轮转三种进程调度算法的统一模拟、指标计算和边界验证。通过甘特图和统计数据可以明确看到：SJF 将平均等待时间从 11.40 降低到 8.20，整体效率最好；RR(q=2) 的平均首次响应时间为 2.80，交互响应最好，但平均等待时间和切换次数最高；FCFS 结构最简单，却容易产生护航效应。

实验过程中对就绪队列入队顺序、空闲时钟推进和等待时间定义的修正，比单纯实现算法代码更有价值。它说明调度程序正确性依赖于明确的不变量、可复现输入和自动化断言。后续可以继续实现优先级调度、多级反馈队列和带上下文切换开销的模型，并通过随机进程集比较不同负载下的性能变化。
